## 2024-04-28 - [CRITICAL] Prevent Command Injection via Unsanitized Filenames
**Vulnerability:** Found `execFile` calls passing user-provided filenames (derived from `filePath` and `fp` during file staging) to a command-line tool (Assimp) without strict character validation. This could allow command or argument injection if a maliciously named `.dae` file (e.g., containing `$(...)`, `;`, `&`, etc.) was processed.
**Learning:** Even though `execFile` does not spawn a shell by default, preventing traditional shell injection, it is still vulnerable to argument injection if a filename starts with `-` (which was mitigated by `./` prepending) or contains confusing escape characters depending on the child process parser. More importantly, strict filename validation (`/^[a-zA-Z0-9_\-\. ]+$/`) acts as an immediate, clean defense-in-depth layer before the filename ever touches the file system operations or child process APIs. Additionally, we learned that running background processing queues requires handling validation failures gracefully by using `setImmediate(processQueue)` instead of throwing or exiting, to ensure the application stays alive.
**Prevention:** Always validate all external input (including paths and filenames) against strict allowlists before passing them to file system APIs or `child_process` execution.
