## 2024-05-24 - [CRITICAL] Fix command injection risk in GLB conversion
**Vulnerability:** Command injection risk in `server.js` within `processQueue()` and the Staging watcher. Filenames containing malicious characters (like shell metacharacters or flags starting with a hyphen) derived from user-uploaded or watched DAE files could be passed unsanitized to `execFile`. While `execFile` does not execute through a shell by default, poorly formatted filenames might still be misinterpreted by the `assimp` executable as commands or unexpected arguments if not validated.
**Learning:** `execFile` protects against simple shell injection (e.g., using `&&` or `|`), but it does not protect against malicious command-line arguments. Although there was some minimal prefixing of paths (`.\\` or `./`) which mitigates flag injection, true validation of the raw `inputFilename` and `outputGlb` was missing. Filenames with malicious strings or specific whitespace patterns might lead to unintended execution flow.
**Prevention:** Always validate all external inputs (including those derived from filenames read from the filesystem) against a strict whitelist regular expression (e.g., `const SAFE_FILENAME_REGEX = /^[a-zA-Z0-9_\-\.\ ]+$/;`) before passing them to any child process function. If validation fails, reject the input immediately.
