## 2024-05-24 - Static Asset Exposure Vulnerability
**Vulnerability:** Static administrative files (`/admin/tagger.html`) and staging assets (`/showroom/staging/test.glb`) were publicly accessible without authentication, despite the API endpoints managing them being protected.
**Learning:** In Express applications relying on `express.static`, API route protection (e.g. mounting `adminAuth` on `/api/showroom/staging`) does not cascade to the static file serving middleware for the same conceptual paths if the physical file paths (`public/admin` or `Showroom/staging`) are exposed by a broad `express.static` catch-all or a separately mounted but unprotected static route. This creates a split-brain authorization issue where data APIs are secure but the physical assets are public.
**Prevention:** Always mount explicit authentication middleware ahead of `express.static` for sensitive directories, ensuring both dynamic API routes and static asset delivery are protected by the same security policies.
