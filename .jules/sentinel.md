## 2024-06-08 - Fixed Unauthenticated Static Asset Access
**Vulnerability:** Static files in `/admin` (like `tagger.html`) and `/showroom/staging` (sensitive GLB files) were exposed to unauthenticated users. This occurred because API endpoints under `/api/showroom/staging` were protected by `adminAuth`, but the corresponding express static routes serving the physical files were completely unprotected or served by a global catch-all.
**Learning:** Securing API routes does NOT automatically secure static file delivery for related directories. Express middleware operates sequentially; a catch-all `express.static('public')` will serve anything in that folder unless a specific route *with authentication* intercepts it first.
**Prevention:** Always explicitly bind authentication middleware directly to the `app.use('/route', auth, express.static(...))` declaration for sensitive directories. Furthermore, when defining overlapping static routes (e.g., `/showroom` and `/showroom/staging`), ensure the more specific, protected route is declared *before* the general catch-all to prevent middleware shadowing.
